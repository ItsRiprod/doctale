# Doctale → Fumadocs migration: orchestration plan

Status: **Phase 0 done (2026-11-11), Phase 1 ready to dispatch** · Target branch: `fumadocs` · Written 2026-11-11

## Goal

Replace Astro + Starlight with **Next.js + Fumadocs (UI + MDX) + Tailwind v4**, styled with
Catalyst where it fits, deployed as a **static export** to the same Cloudflare Workers static
assets setup. Text is being rewritten later, so the deliverable is the *platform*: every widget,
behaviour and deploy path that exists today, working and themed, with the current pages ported
mechanically so they double as a regression suite.

## Non-goals

- Rewriting doc text (separate effort after cutover).
- Touching `hy*Server-extracted-*` folders (left as-is; excluded from the build).
- Rebuilding the docs layout from Catalyst's `sidebar-layout`. Fumadocs' `DocsLayout` stays the shell;
  Catalyst supplies styled primitives (see §4).

## 2. The contract (frozen in Phase 0, everyone builds against it)

This is what lets WS-B/C/D run in parallel without waiting on each other.

1. **Content location:** `content/docs/**`, same relative paths as `legacy/astro/src/content/docs/**`.
   Docs are served from the site root (`docsRoute = '/'`, route `app/(docs)/[...slug]`), so URLs are unchanged.
   The home page is the route `app/(home)/page.tsx`. The codemod does **not** port `index.mdx`; its content goes to WS-A.
2. **No component imports in content.** All widgets are global, registered in `components/mdx.tsx` (`getMDXComponents`).
   The codemod strips `import … from '@astrojs/starlight/components'`.
3. **Legacy names stay valid** (shims in `components/mdx/legacy.tsx`):
   `Aside, Tabs, TabItem, Steps, FileTree, Card, CardGrid, LinkCard, Badge`. Props are kept exactly as
   Starlight's (`type`, `title`, `label`, `text`, `variant`, `href`, `description`, `icon`).
   New content may use native Fumadocs names: `Callout, Tab, Step, Files, Folder, File, Cards, Accordion(s), TypeTable,
   Banner, InlineTOC`. Native `Tabs`/`Steps` collide with legacy names, so they're registered as `FdTabs`/`FdSteps`. The legacy
   `Card` overrides the native `Card`, so WS-B's `Card` shim must also accept the native props (`href`, `description`).
4. **Frontmatter:** `title`, `description` (required). `template`/`hero` are removed by the codemod (home is custom).
5. **Code fence meta** stays Starlight/Expressive Code compatible: `title="…"`, `{ranges}`, `wrap`.
6. **Mermaid** stays a plain ```` ```mermaid ```` fence. fumadocs-core's `remarkMdxMermaid` turns it into `<Mermaid chart="…" />`.
8. **MDX pipeline config** lives in `lib/source.ts` (`defineDocs` from `fumadocs-mdx/macro`, `mdxOptions: applyMdxPreset(…)`).
   This template has **no `source.config.ts`**.
9. **Theming:** `data-theme="<id>"` goes on `<html>` (the same element as `.dark`). shadcn.css resolves `--color-fd-*` on `:root`,
   so the attribute anywhere else does nothing. The default theme's CSS also targets bare `:root` / `.dark`. `?theme=<id>` overrides for QA.
7. **File ownership** (avoid merge conflicts):
   - WS-A: `app/layout.tsx`, `app/(home)/**`, `lib/layout.shared.tsx`, `lib/shared.ts`, `components/provider.tsx`, `app/global.css` (theme section), `components/theme/**`, `components/catalyst/**`, `app/themes/**`, `scripts/themes/**`
   - WS-B: `components/mdx.tsx`, `components/mdx/**` (except `mermaid.tsx`, `image.tsx`), `content/docs/_kitchen-sink.mdx`
   - WS-C: `lib/source.ts` (the `mdxOptions` block only), `components/mdx/mermaid.tsx`, `components/mdx/image.tsx`, `app/global.css` (code/mermaid section)
   - WS-D: `content/**` (except `_kitchen-sink.mdx`), `scripts/codemod/**`, and deleting `content/docs/test.mdx`
   - WS-E: `next.config.mjs`, `app/api/search/**`, `app/sitemap.ts`, `app/not-found.tsx`, `app/llms*/**`, `app/og/**`, `public/**`, `wrangler.toml`, `.github/**`, `package.json` scripts
   - `app/(docs)/**` belongs to the lead. WS-C sends its `components/mdx.tsx` registrations to WS-B, or the lead adds them at integration.
   - `legacy/astro/**` is read-only for everyone (codemod input and reference).

### Phase 1: parallel workstreams

Each runs in its own git worktree off `fumadocs` (after Phase 0), and opens a PR or a mergeable branch into `fumadocs`.

#### WS-A: Theme, shell and home (Catalyst-heavy)
- `DocsLayout`/`HomeLayout` via `baseOptions` (logo, title "Hytale Server Modding", GitHub link).
- **Themes are pulled from the registry. No local or custom themes.** The old 4 accents and the custom
  `custom.css` palette are dropped. Import `fumadocs-ui/css/shadcn.css` (Fumadocs reads shadcn/ui variables);
  every theme is a pulled shadcn registry item. Leave out the ~1400 lines of Starlight CSS entirely.
- **Theme puller** `scripts/themes/pull.mjs`:
  - `npm run theme:sync`: fetch the index `https://tweakcn.com/r/registry.json` (36 themes when checked 2026-11-11)
    and pull **every** item, brand-named ones included (the user picks; no filtering). Removes themes that left the index
    (and says so). This is the normal path, re-run whenever.
  - `npm run theme:add <name|url|file>`: one extra item from any shadcn-registry URL or a tweakcn-editor JSON export.
  - `npm run theme:list`: print the index.
  - Item format: `registry:style` JSON, `cssVars.light` / `cssVars.dark` / `cssVars.theme`, e.g. `https://tweakcn.com/r/themes/<name>.json`.
  - Output: vendored `app/themes/<name>.css` (`[data-theme="<name>"]{…}` + `.dark[data-theme="<name>"]{…}`) with a header
    comment giving the source URL and pull date, plus a generated `app/themes/index.ts` (`{ id, label, swatch: {light, dark} }`, swatch =
    `primary`/`background`). Committed, so no runtime fetch and builds are reproducible.
  - Filter: keep colour vars + `radius`. Drop `font-*`, `tracking-*`, `shadow-*` and `css` (we keep Inter/JetBrains Mono) unless `--with-fonts`.
  - Unknown/missing vars fall back to the shadcn.css defaults; the script warns about items missing core vars.
- **Default theme:** a single constant `DEFAULT_THEME` in `app/themes/config.ts` (initial value `modern-minimal`, change freely).
- **Code theme per site theme:** the registry carries no code theme, so `app/themes/config.ts` also has
  `codeThemes: Record<id, {light, dark}>` overrides (bundled Shiki names). Everything else falls back to `github-light`/`github-dark`.
  The generated index merges these in. WS-C reads the merged list.
- **Catalyst on theme vars:** the copied Catalyst files hard-code `zinc-*`/`blue-*` utilities. Add a
  `primary`/`neutral` colour variant that uses theme tokens (`bg-primary`, `text-primary-foreground`, `border-border`)
  and use those variants across the site, so every pulled theme reaches Catalyst parts too.
- Theme + scheme picker: Catalyst `Dropdown` (long list is fine; alphabetical, swatch per item, scrollable, type-ahead)
  plus a separate light/dark/system toggle. Writes `localStorage` `doctale-theme`; an inline `<head>` script sets `data-theme`
  before paint (no flash). An unknown or removed id falls back to `DEFAULT_THEME`. Light/dark via `next-themes` (`attribute="class"`).
  No migration of old `starlight-*` keys.
- Home page: hero (logo, tagline "By modders, for modders.", Get Started and GitHub buttons via Catalyst
  `Button`), two entry cards (Asset Development / Plugin Development), "A Quick Taste" Java snippet.
- Fonts via `next/font` (Inter, JetBrains Mono) mapped to `--font-sans`/`--font-mono`.
- Root metadata (title template, description, OpenGraph). `theme-color` set at runtime from the active theme's `--background`.
- **Done when:** every registered theme × light/dark switches with no flash on hard reload; home page matches or beats current; Lighthouse a11y ≥ 95.

#### WS-B: MDX widget library and kitchen-sink page
- Implement every legacy shim from §2 on top of Fumadocs components:
  - `Aside`: map `note→info`, `tip→idea` (or `success`), `caution→warn`, `danger→error`; `title` passthrough.
  - `Tabs`/`TabItem`: collect `label` from children → `items`; support `syncKey` → `groupId` + `persist`.
  - `FileTree`: walk the markdown `<ul>` children; trailing `/` or nested list = folder; support
    `**bold**` highlight and trailing comments like Starlight does.
  - `Steps`: style the child `<ol>` with Fumadocs step styles.
  - `CardGrid`→`Cards`, `Card` (title, icon), `LinkCard` (title, description, href → `Card href`).
  - `Badge`: Catalyst `Badge` with variant→colour map (`note`, `tip`, `caution`, `danger`, `success`, `default`).
- Register native Fumadocs components too (`Callout, Tab, Steps/Step, Files/Folder/File, Cards/Card,
  Accordion/Accordions, TypeTable, Banner, InlineTOC`), and style markdown tables with Catalyst `Table` look.
- `content/docs/_kitchen-sink.mdx`: every widget in every variant, nested cases (Aside in Tabs,
  FileTree in Steps, code in TabItem). This page is the shared visual test target.
- **Done when:** kitchen sink renders all variants in light/dark; no React key/hydration warnings.

#### WS-C: Code, diagrams and images
- `lib/source.ts` `mdxOptions` → `rehypeCodeOptions`: **multi-theme Shiki**. Generate the `themes` map from
  the merged theme index from WS-A (each theme's `{light, dark}` Shiki pair, default `github-light`/`github-dark`; load only the distinct Shiki themes used),
  set `defaultColor: false`, and add CSS that picks `--shiki-<theme>-<scheme>` from `[data-theme]` + `.dark`.
  Until WS-A lands, stub the registry with `github-light`/`github-dark`.
  `langs` list from §1, transformers: meta highlight, plus a small one for `wrap`.
  `title="…"` rendered in the Fumadocs code-block header with copy button.
- Mermaid: remark plugin turns fences into `<Mermaid chart="…" />`. Client component lazy-loads
  `mermaid`, re-renders on theme or scheme change, using `themeVariables` read from the active theme's CSS vars (`--primary`, `--card`, `--border`, `--chart-1..5`),
  and click toggles `requestFullscreen` (with a visible hint, ported from `.mermaid::after`).
- Images: `img` override → `ImageZoom` with caption from `title` (or alt), as the Starlight plugin did;
  `unoptimized` for static export.
- **Done when:** all 43 mermaid fences in the ported content render (WS-D output) in both schemes; spot-check
  10 highlighted/titled code blocks; zoom works on keyboard and touch.

#### WS-D: Content pipeline (codemod)

  1. Copy `legacy/astro/src/content/docs/**` (minus root `index.mdx`) → `content/docs/**`.
  2. Strip Starlight imports; drop `template`/`hero` frontmatter; keep `title`/`description`.
  3. Convert `legacy/astro/astro.config.mjs` `sidebar` → `meta.json` per folder (`title`, `pages` order,

- Verify every old URL maps to the same new URL; emit `scripts/codemod/url-map.json` (old→new; should be identity).
- **Done when:** codemod runs clean twice, all ~100 pages compile against the Phase 0 stubs, and the sidebar

- `app/sitemap.ts`, `robots.txt`, `_headers` (port caching headers; add long cache for `/_next/static/*`),

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| shadcn var names drift (v4 uses OKLCH, `--sidebar-*`, `--chart-*`) | Pin the theme format tweakcn exports at Phase 0; `shadcn.css` bridge only needs the core vars |
| Fumadocs API drift (fast-moving project) | Phase 0 pins versions and verifies each spike before briefs go out |
| FileTree shim mis-parses edge cases | Kitchen sink covers them; codemod report flags weird trees; can hand-convert to `<Files>` (45 instances) |
| Static export rejects a dynamic route (search/OG) | WS-E owns it; OG images either static per-section or dropped for v1 |
| Mermaid bundle size / flash | Lazy client import, render placeholder with fixed min-height |
| Catalyst licence on a public repo | Only adapted component files committed, never the zip; confirm Tailwind Plus terms for OSS end products before Phase 3 |
| Theme flash with two-attribute theming | Inline pre-paint script (same approach as today) + `suppressHydrationWarning` on `<html>` |
